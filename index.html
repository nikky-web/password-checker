        How the estimate works

        01

        Attackers don't guess randomly

        Cracking tools start with leaked password lists, then dictionary words with l33t swaps, years, and keyboard runs like qwerty. So Summer2024! ticks every box on a typical "rules" list and still falls almost instantly. This checker scores the pieces the way a cracker would, not by counting character types.

        02

        Speed depends on where they attack

        A login page with lockouts allows maybe 100 tries an hour. A stolen database is a different story: if the site hashed passwords with fast MD5 or SHA-1, one GPU rig can test about 10 billion guesses a second. Slow hashes like bcrypt drop that to thousands. Assume the worst case.

        03

        Breach check without leaking

        The breach lookup uses k-anonymity. Your browser hashes the password with SHA-1 and sends only the first 5 hex characters. The API returns every leaked hash starting with that prefix (hundreds of them), and the match happens locally. Nobody learns what you typed.
